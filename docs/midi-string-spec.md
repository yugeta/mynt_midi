===

```
Create : 2025-04-25

# 概要

MYNT MIDI 独自のテキスト音符記法。
MSX BASIC の PLAY 文に着想を得た、軽量なテキストベースの音楽データ形式。
厳密な MIDI 規格ではなく「MIDIイズム」的な独自仕様。

参考: https://blog.myntinc.com/2023/09/midi-1se.html


# 文法

## パース正規表現

```
/(\\[(.+?)\\]|[A-G~STOV]+?)([0-9\+\-]*)/gi
```

マッチグループ:
- グループ1: コマンド部（`[...]` 和音 or 単一文字 `A-G`, `~`, `S`, `T`, `O`, `V`）
- グループ2: 和音の中身（`[...]` の場合のみ）
- グループ3: 値部（数値、`+`、`-`）


## トークン定義

### 状態変更トークン（音符データを生成しない）

| トークン | 書式 | 説明 | デフォルト |
|---|---|---|---|
| テンポ | `T{数値}` | 4分音符が1分間に鳴る回数。以降の音符の長さを変更 | 120 |
| オクターブ | `O{数値}` | オクターブ指定（0〜10）。以降の音符のオクターブを変更 | 5 |
| 音量 | `V{数値}` | 音量。以降の音符の音量を変更 | 50 |

### 音符生成トークン（音符データを生成する）

| トークン | 書式 | 説明 |
|---|---|---|
| 音名 | `C`, `D`, `E`, `F`, `G`, `A`, `B` | ドレミファソラシ |
| シャープ | `{音名}+` | 半音上げ（例: `C+` = ド#） |
| フラット | `{音名}-` | 半音下げ（例: `D-` = レ♭ = ド#） |
| 休符 | `S` | 無音（現在のテンポ分の長さ） |
| フェードアウト | `~` | 音量を0にフェード |
| 和音 | `[{音符列}]` | 角括弧内の音を同時に鳴らす |

### 特殊ルール

- スペースは無視される（可読性のための区切り）
- 大文字・小文字は区別しない（パース時に toUpperCase）
- 和音内では T, O, V の状態変更が独立（外側の状態に影響しない）
- 和音は1つのデータとして扱われ、tempo は1音分


## 音名→MIDIノート番号の変換

```
MIDIノート番号 = (オクターブ × 12) + 音名オフセット
```

| 音名 | オフセット | 異名同音 |
|---|---|---|
| C | 0 | B+ |
| C+ / D- | 1 | |
| D | 2 | |
| D+ / E- | 3 | |
| E | 4 | F- |
| F | 5 | E+ |
| F+ / G- | 6 | |
| G | 7 | |
| G+ / A- | 8 | |
| A | 9 | |
| A+ / B- | 10 | |
| B | 11 | C- |

## MIDIノート番号→周波数の変換

```
freq = 440 × 2^((midi - 69) / 12)
```

- A4（オクターブ5、音名A）= MIDIノート69 = 440Hz


## テンポ→音の長さの変換

```
duration(秒) = (60 / tempo) × (4 / length)
```

- `length` は常に 4（4分音符固定）
- 簡略化: `duration = 60 / tempo`

| テンポ値 | 1音の長さ | 用途例 |
|---|---|---|
| T120 | 0.500秒 | 標準テンポ |
| T300 | 0.200秒 | やや速い |
| T450 | 0.133秒 | 速い（1upサウンド） |
| T600 | 0.100秒 | 速い（コイン音の前半） |
| T800 | 0.075秒 | 非常に速い |
| T3000 | 0.020秒 | 超高速（効果音向け） |
| T4000 | 0.015秒 | 超高速（効果音向け） |


# サンプル解析

## サンプル1: コイン音

```
T600O6BT100O7E~
```

パース結果:

| # | トークン | 状態変更 | 生成データ | tempo(秒) | time(秒) |
|---|---|---|---|---|---|
| 1 | T600 | T=600 | — | — | — |
| 2 | O6 | O=6 | — | — | — |
| 3 | B | — | O6 B | 0.100 | 0.100 |
| 4 | T100 | T=100 | — | — | — |
| 5 | O7 | O=7 | — | — | — |
| 6 | E | — | O7 E | 0.600 | 0.700 |
| 7 | ~ | — | フェードアウト | 0.600 | 1.300 |

全体再生時間: 1.300秒

解説:
- 最初の B は T600（速い）で短く鳴る
- 途中で T100（遅い）に変更し、E を長く鳴らす
- 最後に ~ でフェードアウト

## サンプル3: ドカン（爆発音）

```
T3000O7EO6ADO7EO6ADO5GCO4FO3B T800S T3000O7EO6ADO7EO6ADO5GCO4FO3B T800S T3000O7EO6ADO7EO6ADO5GCO4FO3B

パース結果（最初のフレーズのみ）:

| # | トークン | 生成データ | tempo(秒) | time(秒) |
|---|---|---|---|---|
| 1 | T3000 | — | — | — |
| 2 | O7 E | O7 E | 0.020 | 0.020 |
| 3 | O6 A | O6 A | 0.020 | 0.040 |
| 4 | D | O6 D | 0.020 | 0.060 |
| ... | ... | ... | ... | ... |
| N | T800 | — | — | — |
| N+1 | S | 休符 | 0.075 | ... |

解説:
- T3000 で超高速に音を連打（爆発の「ドカン」部分）
- T800 S で短い無音（間）を入れる
- 同じパターンを3回繰り返す

# パーサーの既知の問題

## 1. 和音内の状態変更が外側に影響しない

和音 `[O5cO6c]` 内で O が変更されても、和音の外側の O は変わらない。
これは `str2datas()` が独立した状態変数で和音内をパースするため。
→ 仕様通りの動作（問題なし）

## 2. 和音のテンポは外側のテンポに従う

和音 `[...]` 全体で1つの `tempo` が適用される。
和音内で T を変更しても、和音全体の長さは変わらない。

## 3. 音名の後の値が +/- の場合

`C+` はシャープ、`D-` はフラットとして処理される。
正規表現の `([0-9\+\-]*)` で値部としてキャプチャされ、
音名 + 値 で `chord2singleNum()` に渡される。


# エンコード（データ→文字列）の要件

DOM 上の音符からMIDI文字列を正確に復元するために必要な情報:

| 情報 | 必須 | 現在のDOM | 復元可能性 |
|---|---|---|---|
| オクターブ | ✅ | data-octave | ○ |
| 音名 | ✅ | data-key | ○ |
| テンポ (T値) | ✅ | なし | × 逆算不可 |
| 音量 (V値) | ✅ | なし | × |
| 時間位置 | ✅ | style.left (px) | △ 変換係数が必要 |
| 和音グループ | ✅ | 同じleftの音符 | △ 近似的に判定可能 |
| 休符 | ✅ | なし | × 音符間の隙間から推測 |
| フェードアウト | ✅ | なし | × |

結論: DOM だけからの正確なエンコードは不可能。
データモデルの導入が必須。
