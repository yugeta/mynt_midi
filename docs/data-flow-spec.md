# 概要

本ドキュメントは、MIDI文字列・MIDIデータ配列・エディタ上の音符（DOM）・音声再生の間の
データ変換フローと、各データ形式の仕様を定義する。


# データ形式

## 1. MIDI文字列

textarea に入力されるテキスト形式。人間が読み書きする。

```
T4000 [O5fO6fO7f][O2cO3cO4c][O4eO5eO6e][O3bO4bO5b] T300S T4000 [O5fO6fO7f]...
```

### トークン一覧

| トークン | 書式 | 説明 | 例 | 状態変更 |
|---|---|---|---|---|
| テンポ | `T{数値}` | 4分音符が1分間に鳴る回数 | `T4000` | 以降の音符のtempoを変更 |
| オクターブ | `O{数値}` | オクターブ指定（0〜10） | `O5` | 以降の音符のOを変更 |
| 音量 | `V{数値}` | 音量（デフォルト50） | `V80` | 以降の音符のvolumeを変更 |
| 音名 | `{A-G}[+\-]` | ド〜シ、シャープ/フラット | `C`, `F+`, `B-` | 音符データを生成 |
| 休符 | `S` | 無音（1音分の長さ） | `S` | 無音データを生成 |
| フェードアウト | `~` | 音量を0にフェード | `~` | フェードデータを生成 |
| 和音 | `[...]` | 角括弧内の音を同時に鳴らす | `[O5cO6c]` | 和音データを生成 |

### パース時の状態変数

| 変数 | 初期値 | 説明 |
|---|---|---|
| T | 120 | 現在のテンポ |
| O | 5 | 現在のオクターブ |
| V | 50 | 現在の音量 |
| tempo | tdur(120, 4) = 0.5秒 | 現在の1音の長さ（秒） |
| time | 0 | 累積再生時間（秒） |

### テンポ→秒の変換

```
tdur(tempo, length) = (60 / tempo) * (4 / length)
```

- `length` は常に 4（4分音符）
- 例: `T4000` → `(60 / 4000) * 1` = `0.015秒`
- 例: `T120` → `(60 / 120) * 1` = `0.5秒`
- 例: `T300` → `(60 / 300) * 1` = `0.2秒`


## 2. MIDIデータ配列

`MidiParser.get_code()` が返す配列。各要素は1つの音符/休符/フェードを表す。

```js
{
  O      : 5,           // オクターブ（音名の場合のみ）
  S      : "C",         // 音名文字列 / "S"(休符) / "~"(フェード) / "[...]"(和音)
  num    : 60,          // MIDIノート番号（音名→数値変換後）
  tempo  : 0.015,       // この音符の長さ（秒）
  freq   : 261.63,      // 周波数（Hz）/ 和音の場合は配列
  volume : 50,          // 音量
  time   : 0.015,       // 累積再生時間（この音符の終了時点、秒）
}
```

### 重要な関係

- `time` = 前の音符の `time` + この音符の `tempo`
- 最後の要素の `time` = 全体の再生時間（duration）
- 音符の開始時点 = `time - tempo`


## 3. エディタ上の音符（DOM .note 要素）

エディタに配置される div 要素。

```html
<div class="note"
  style="left: 100px; top: 30px; width: 50px;"
  data-type="key"
  data-octave="5"
  data-key="c"
  data-status="active">
</div>
```

### 属性一覧

| 属性 | 説明 | 値の例 |
|---|---|---|
| `style.left` | タイムライン上のX位置（px） | `100px` |
| `style.top` | 鍵盤上のY位置（px） | `30px` |
| `style.width` | 音符の表示幅（px） | `50px`（固定） |
| `data-type` | 鍵盤タイプ | `key` / `flat` |
| `data-octave` | オクターブ番号 | `0`〜`10` |
| `data-key` | 音名（小文字） | `c`, `f`, `b-` |
| `data-status` | 選択状態 | `active` / なし |

### DOM に保持されていない情報（欠落）

| 情報 | 説明 |
|---|---|
| テンポ (T) | 音符の長さを決めるテンポ値 |
| 音量 (V) | 音符の音量 |
| 累積時間 (time) | 再生タイムライン上の正確な時間位置 |
| 音符の長さ (tempo) | この音符が何秒鳴るか |


## 4. 音声再生スケジュール

`MidiPlayer.sound()` が Web Audio API に渡すスケジュール。

- `OscillatorNode.frequency.setValueAtTime(freq, startTime + time)`
- `OscillatorNode.start(startTime)`
- `OscillatorNode.stop(startTime + totalTime)`

時間基準: `AudioContext.currentTime`（秒）


# 現在のデータフロー

```
[A] MIDI文字列 (textarea)
     │
     │ MidiParser.get_code()  [デコード: 文字列→データ配列]
     ▼
[B] MIDIデータ配列
     │
     ├──→ StringInput.string2editor()  [データ配列→DOM]
     │     音符配置: left = (startTime / totalDuration) * timelineWidth
     │         ▼
     │    [C] DOM .note 要素
     │
     └──→ MidiPlayer.sound()  [データ配列→音声]
               ▼
          [D] Web Audio API スケジュール
```

## 変換の方向と状態

| 変換 | 方向 | モジュール | 状態 |
|---|---|---|---|
| A → B | デコード | MidiParser.get_code() | ✅ 安定（可逆） |
| B → C | 表示 | StringInput.string2editor() | ⚠️ 情報欠落（tempo, volume, time が失われる） |
| B → D | 再生 | MidiPlayer.sound() | ✅ 安定 |
| C → A | エンコード | MidiSerializer.editor2string() | ❌ 不安定（テンポ逆算が不正確） |
| A → B → C → A | ラウンドトリップ | 上記の組み合わせ | ❌ 壊れる（情報欠落によりテンポが変わる） |


# 問題点

## 1. DOM に情報が欠落している

DOM の `.note` 要素には `data-octave` と `data-key` しかなく、
テンポ・音量・正確な時間位置が保持されていない。
そのため DOM → MIDI文字列 の逆変換でテンポを正確に復元できない。

## 2. エンコード（DOM → 文字列）のテンポ逆算が不正確

`serializer.js` はピクセル位置の差分からテンポを逆算しているが:
- ピクセル→時間の変換に textarea の現在値を使うため、フィードバックループが発生
- 浮動小数点の丸め誤差が蓄積
- 元のテンポ値（T4000 等）を正確に復元できない

## 3. ラウンドトリップで音が壊れる

文字列 → データ → DOM → 文字列 の変換を繰り返すと、
テンポ値が毎回変わり、音が大幅に変化する。


# 解決方針: データモデルの導入

DOM を中間データとして使わず、メモリ上にデータモデルを保持する。

```
[A] MIDI文字列 (textarea)
     │ ↑
     │ │ MidiParser.get_code() / MidiModel.toString()
     ▼ │
[M] MIDIデータモデル (メモリ上の配列) ← 信頼できる唯一のデータソース
     │ ↑
     │ │ render() / DOM操作時にモデルを更新
     ▼ │
[C] DOM .note 要素 (表示用)
     │
     └──→ [D] 音声再生（モデルから直接再生）
```

### データモデルが保持する情報

```js
{
  id       : "note_001",   // 一意のID（DOM要素との紐付け用）
  octave   : 5,            // オクターブ
  key      : "c",          // 音名
  tempo    : 4000,         // テンポ値（T値そのもの）
  duration : 0.015,        // 音の長さ（秒）
  volume   : 50,           // 音量
  time     : 0.015,        // 累積再生時間（秒）
  left     : 100,          // エディタ上のX位置（px）
  chord    : ["note_002"], // 和音グループ（同時に鳴る音符のID）
}
```

### メリット

- テンポ・音量が保持されるので、エンコード時に正確に復元できる
- DOM 操作（移動）時はモデルの `left` と `time` を更新するだけ
- ラウンドトリップで情報が失われない
- 再生もモデルから直接行えるので、textarea のパースが不要

## ツールの目的

- ブラウザゲーム用の軽量音声データ（SE・ジングル）を作成するツール
- 厳密なMIDI規格ではなく「MIDIイズム」的な独自テキスト音データ
- MSX BASIC の PLAY 文に着想を得た記法
- サーバーサイド不要、バニラJSフレームワークで構築
- 完成後は無料公開、作成した音源データの著作権は作成者に帰属

## 設計方針

- アジャイル的に開発（事前設計を完璧にせず、作りながら仕様を固める）
- 単体機能をできるだけ細かなモジュール化し、他の機能との依存関係を無くす
- 音符機能は今後の仕様変更が大きい可能性があるため、変更を容易にする設計
- `ui/` フォルダが初期版（ブログ公開時点）、`src/` が本格開発版

## 作者が認識していた課題（ブログ #4, #5 より）

### 座標と時間軸の兼ね合い（#4）

> タイムラインエディター系の処理を作る時に、いつも悩ましいのが、座標と時間軸との兼ね合いです。

- ミリ秒単位での厳密な再生が必要
- 表示部分は同期が取れていれば厳密でなくてよい
- `requestAnimationFrame()` で処理時間差をカーソル移動距離にする方式を採用

### 再生方式の悩み（#4）

> 音符の時間軸に並べたものをそのまま音を出して再生するのと、
> 最終的に書き出すMIDI文字列データに変換して、単にそれを再生するという処理にするかを悩み中です。

→ 最終的に「MIDI文字列をパースして再生」する方式を採用。
  エディタ上の音符から直接再生する方式は採用されなかった。

### 音符→文字列変換（#5）

> 次回は、音符から文字列を作る処理を作ってみたいと思います。

→ この機能は未完成のまま残されていた。
  不足機能として明記:
  - 音符 to midi文字列変換機能
  - 音符のサイズ（テンポ）変更機能
  - 独自midiファイルの出力/入力機能
  - 全体テンポ切り替え機能

### 和音の設計（#5）

> `[CEG]`（ドミソ和音）のように、ブラケットで書く配列のように記述することで、
> ブラケット内の音を同時に鳴らすという仕様にしてみました。

デメリットとして作者自身が認識:
- 同じ和音は同じテンポでしか書けない
- 互い違いに音を鳴らす場合は、ブラケットを切り替える必要がある

# 実装済み: データモデルの導入

## 修正内容（2025-04-25）

DOM からテンポを逆算する不安定な方式を廃止し、
メモリ上のデータモデル（MidiModel）を信頼できる唯一のデータソースとして導入した。

### 新規ファイル

`src/js/midi/model.js` — MidiModel クラス

### 修正ファイル

| ファイル | 変更内容 |
|---|---|
| `midi/serializer.js` | DOM→テンポ逆算を廃止。モデル経由で文字列生成に変更 |
| `controller/string-input.js` | MidiModel.fromString() でモデル構築後に DOM 描画 |
| `ui/editor.js` | 音符配置時に MidiModel.addNote() でモデルにも追加 |


## 新しいデータフロー

```
[A] MIDI文字列 (textarea)
     │                    ↑
     │ fromString()       │ toString()
     ▼                    │
[M] MidiModel ─────────────┘
     │  ↑
     │  │ syncDomToModel()（DOM位置→モデル反映）
     │  │
     │  renderFromModel()（モデル→DOM描画）
     ▼  │
[C] DOM .note 要素 (data-model-id でモデルと紐付け)
```

### 変換の方向と状態（更新後）

| 変換 | 方向 | モジュール | 状態 |
|---|---|---|---|
| A → M | デコード | MidiModel.fromString() | ✅ 安定 |
| M → A | エンコード | MidiModel.toString() | ✅ 安定（テンポ値を保持） |
| M → C | 描画 | StringInput.renderFromModel() | ✅ 安定 |
| C → M | 位置同期 | MidiSerializer.syncDomToModel() | ✅ 安定（left のみ同期） |
| A → M → C → M → A | ラウンドトリップ | 上記の組み合わせ | ✅ 安定 |


## MidiModel のデータ構造

```js
{
  id        : "note_0",     // 一意のID（DOM の data-model-id と対応）
  octave    : 5,            // オクターブ（0〜10）
  key       : "c",          // 音名（小文字）
  tempo     : 0.015,        // 音の長さ（秒）= 60 / tempoVal
  tempoVal  : 4000,         // テンポ値（T値そのもの、整数）
  volume    : 50,           // 音量
  time      : 0.015,        // 累積再生時間（秒、この音符の終了時点）
  startTime : 0,            // この音符の開始時点（秒）
  left      : 100,          // エディタ上のX位置（px）
  chordId   : "chord_0",   // 和音グループID（同時に鳴る音符は同じID）
  type      : "note",       // "note" / "rest" / "fade"
}
```

### type の種類

| type | 説明 | octave/key |
|---|---|---|
| `note` | 音符（音が鳴る） | 値あり |
| `rest` | 休符（無音） | null |
| `fade` | フェードアウト | null |

### DOM との紐付け

- DOM の `.note` 要素に `data-model-id` 属性を付与
- `data-model-id` の値はモデルの `id` と一致
- 音符移動時: DOM の `offsetLeft` → `syncDomToModel()` → モデルの `left` を更新
- 文字列同期時: モデルの `toString()` → textarea に書き込み


## MidiModel.toString() のエンコード仕様

モデルの音符配列を `left` でソートし、以下のルールで MIDI 文字列を生成:

1. テンポ変更: 前の音符と `tempoVal` が異なる場合のみ `T{値}` を出力
2. 音量変更: 前の音符と `volume` が異なり、かつデフォルト(50)でない場合のみ `V{値}` を出力
3. オクターブ変更: 前の音符と `octave` が異なる場合のみ `O{値}` を出力
4. 単音: `{音名}` を出力（例: `C`, `F+`, `B-`）
5. 和音: 同じ `left` 位置の音符を `[O{oct}{key}O{oct}{key}...]` で出力
6. 休符: `S` を出力
7. フェードアウト: `~` を出力

### エンコード例

モデル:
```
[T4000, O5F] [T4000, O6F] [T4000, O7F]  ← 同じ left（和音）
[T4000, O2C] [T4000, O3C] [T4000, O4C]  ← 同じ left（和音）
[T300, rest]                              ← 休符
```

出力:
```
T4000[O5FO6FO7F][O2CO3CO4C]T300S
```
